SAEP Link Simulator

A weak receiver, such as a Raspberry Pi, gets a stream of images over UDP. It can't afford to process every packet, and the network loses some on the way. SAEP (Semantic-Aware Encoding Protocol) adds a 32-byte summary, a tag, to every packet. The receiver reads the tags and spends its limited CPU on the packets that matter most. This page plays that pipeline live, using the project's real images, tags and trained models.

One image = one frameEach 32×32 test image is cut into a 4×4 grid. Each of the 16 tiles is sent as its own UDP packet.
One packet = 248 bytes24 B header, then the 32 B tag, then the 192 B of pixels. The tag lets the receiver judge a packet without decoding the pixels.
The receiver's budget is kIt can process only k tiles per frame, for example 4 of 16. Its policy decides which ones.
Success = correct labelA small CNN classifies the image from the admitted tiles only. Better choices mean more correct answers for the same CPU.

What just happenedStarting…

ASender

Sends the frame's tiles as 16 packets spread evenly over 40 ms (25 frames per second). Each packet carries its tile's tag. With feedback on, it first ranks its own tiles and sends only the best k.

BLink

Simulates a real network path. A packet can vanish at random (red ✕). If the link is slower than the traffic, packets wait in an 8-slot queue. When the queue is full, newcomers are thrown away (orange). This is called drop-tail.

CReceiver

Reads each packet's tag first, without touching the pixels. Its policy decides which k packets to keep. The rest are skipped (grey). The kept tiles go to the CNN (green), and its compute time grows with every tile. It also sends SAEC feedback back to the sender (purple).

Can this simulation be trusted?

Each of the nine scenarios is run here in the browser over all 300 frames and compared with what the real Python programs measured over real UDP sockets (artifacts/demo_results.json). The chart shows the larger offline experiment on all 10,000 test images.

ScenarioReal UDP runThis pagePackets through link
(real / here)

Each line is one policy. Read it at your budget k (dashed). The context MLP stays highest at small k, which is where it matters. At k = 16 every policy keeps everything, so they meet at 50%.

“exact” means the result matches the real run frame for frame. Without random loss or a capacity limit nothing is random, so the browser and Python must agree exactly, and they do.

“Δ” rows involve chance (random loss, random picks, operating-system timing). Even two real UDP runs differ by a point or two, so agreement within a few points is the expected result.

Why the capacity-limited link behaves oddly. On Windows, link_emulator.py waits in select(), which wakes either on the next packet or on the 15.6 ms system timer. So a link set to 120 packets/s really forwards about 101/s. The packets that survive then fall into a fixed rhythm, often one column of the image. Set the link timing model to “ideal” in step 1 to compare.

Terms used on this page

Short definitions, in the order they appear.

Show the glossary
UDP
A transport protocol that sends packets without retransmission. A lost packet stays lost. That suits live video, where a late packet is useless.
Frame / tile
A frame is one image. It is split into 16 tiles of 8×8 pixels, one per packet.
Tag
32 bytes per packet describing its tile, made by compressing the output of a pretrained vision model (DINOv2) down to 32 signed 8-bit numbers.
Budget k
How many tiles per frame the receiver has CPU time to process. CNN cost grows with every tile: about 1.1 ms for 4 tiles, 3 ms for 16 on this laptop.
Admission policy
The rule that decides which arrived packets get processed.
FIFO
First in, first out: keep the first k packets that arrive. Since tiles are sent row by row, that is usually the top of the image.
int8 tag scorer / XDP
Score = a weighted sum of the tag bytes, using integers only. That simple enough to run inside the Linux kernel's XDP hook. It judges each packet alone, with a threshold τ.
Threshold τ
The score a packet must reach to be kept. It is adjusted automatically so that, on average, about k packets per frame pass.
Context MLP
A small neural network (8.4 k weights) that scores each tag relative to the other tags in the same frame. It needs the whole frame first, so it runs in user space.
Oracle
Cheats by using the true label to pick the most useful tiles. Not a real policy: it shows the best possible choice.
Drop-tail queue
A buffer in front of a slow link. When it is full, newly arriving packets are discarded. The packets at the tail end lose.
SAEC
The 13-byte control packet the receiver sends back 10 times a second, carrying its budget k and threshold τ.
CRC32
A checksum of the pixel payload in the header. The receiver rejects a packet whose pixels were corrupted.
CIFAR-100
A standard dataset of 32×32 colour images in 100 classes. The CNN reaches 54.7% using all 16 tiles of these 300 images.
